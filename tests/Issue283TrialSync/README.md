# issue#283 Trial challenge ordering regression

Run from the repository root:

```powershell
dotnet run --project tests/Issue283TrialSync/Issue283TrialSync.csproj --no-launch-profile
```

This CPU-only fixture directly links the production synchronization controller and commit message. It does not copy their decision logic into another language. Test doubles provide players/events, transport, location, serialization storage, native combat entry, pending setup, and first-hand consumption. The native choice Prefix/Postfix calls are driven explicitly, with a modeled history append between them.

Coverage includes opposite two-Getter request order, original option before/after commit or after the first-hand hook, immutable first accepted owner, exactly-once entry/setup, mixed-party eligibility, sender/owner scope, host authority, run seed/location, foreign event, wrong page, duplicate/late requests, synchronous entry failure, scope reset, departure, disconnect and handler disposal.

The host's first valid request is accepted only after native ChooseOptionForEvent returns (after SaveEventOptionToHistory). All later challengers are unaccepted requests, not accepted challengers whose setup may be dropped. Clients install the committed owner's setup before their own local native entry, independent of the original option message. Native messages/option history are not suppressed, rewritten or synthesized by the production patches. The START_FIGHT option remains `isProceed: true`; native NEventRoom.BeforeOptionChosen has no asynchronous pre-choice wait on this branch.

The packet double checks field order/preservation, not native bit encoding. First-hand consumption and history are doubles, not evidence that real spirit cards, original history, checksums, rewards, selection tasks, or mixed-party cleanup pass. The fixture does not load Harmony, Godot or sts2.dll, does not compile the mod, and does not launch the game. Native asynchronous entry failure is not observed by the synchronous exception test; a committed decision is never reopened for retry. All actual multiplayer/history/selection/reward cleanup and gameplay acceptance remain NOT_RUN.
